# 用户中心基础功能 · 设计文档

> 版本：v1.0
> 分支：`feature/user-center`
> 交付链路：`feature` 分支开发 → PR 触发 CI 构建验证（不部署）→ 合并 `main` 触发自动部署 → 线上验证

---

## 1. 需求

### 1.1 原始需求

用户中心基础功能：

- **登录相关**：微信登录、苹果登录、手机号登录（验证码服务对接）；手机号需要加密；token 鉴权；（敏感个人信息需要加解密）
- **登出**：token 置 null
- **注销**：`is_deleted = 1`
- **验证**：`http://niuan.top:8080/users` 可直连服务器验证

### 1.2 澄清后的约定

| 议题 | 结论 |
| --- | --- |
| 微信/苹果/短信凭证 | 暂无可用的真实凭证 → 采用「**可配置 + Mock 降级**」：凭证走配置项，未配置时自动使用 Mock 实现（固定验证码、模拟唯一标识），填配置即可对接真实服务 |
| token 方案 | **纯 JWT（无状态）**：登录签发 JWT，鉴权由拦截器解析；登出由客户端丢弃 token，服务端不持久化 token（与原始描述"置 null"略有出入，已确认） |
| 手机号加密 | **确定性 AES 单列**（固定 Key + 固定 IV + pepper）：密文确定性，可直接作为等值查询条件与唯一索引；可解密回显。未采用 md5/sha256（单向不可逆，无法满足"加解密"） |
| 持久层 | 扩展 `users` 表 + **纯 MyBatis**（沿用现有 XML Mapper 手写 SQL 风格） |
| 旧表迁移 | **保留现有数据**，提供 `ALTER TABLE ADD COLUMN` 迁移脚本，由运维在服务器执行一次 |

## 2. 表设计（DDL）

### 2.1 全新环境建表（幂等）`src/main/resources/db/schema.sql`

由 `spring.sql.init.mode=always` 在应用启动时自动执行，用于 CI / 本地 / 全新环境。

```sql
-- 用户表（在原 id/name/email 基础上扩展）
CREATE TABLE IF NOT EXISTS `users` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `name`          VARCHAR(64)  DEFAULT NULL COMMENT '姓名/昵称(兼容旧字段)',
  `email`         VARCHAR(128) DEFAULT NULL COMMENT '邮箱(兼容旧字段,允许为空)',
  `nickname`      VARCHAR(64)  DEFAULT NULL COMMENT '昵称',
  `avatar`        VARCHAR(512) DEFAULT NULL COMMENT '头像URL',
  `phone_cipher`  VARCHAR(255) DEFAULT NULL COMMENT '手机号密文(确定性AES:固定Key+固定IV+pepper)',
  `wechat_openid` VARCHAR(64)  DEFAULT NULL COMMENT '微信openid',
  `apple_sub`     VARCHAR(64)  DEFAULT NULL COMMENT '苹果用户唯一标识sub',
  `is_deleted`    TINYINT      NOT NULL DEFAULT 0 COMMENT '是否注销:0正常,1已注销',
  `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_phone_cipher` (`phone_cipher`),
  UNIQUE KEY `uk_wechat_openid` (`wechat_openid`),
  UNIQUE KEY `uk_apple_sub` (`apple_sub`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 短信验证码表
CREATE TABLE IF NOT EXISTS `user_sms_code` (
  `id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `phone_cipher` VARCHAR(255) NOT NULL COMMENT '手机号密文(与users同规则)',
  `code`         VARCHAR(8)   NOT NULL COMMENT '验证码',
  `expire_time`  DATETIME     NOT NULL COMMENT '过期时间',
  `used`         TINYINT      NOT NULL DEFAULT 0 COMMENT '是否已使用:0未用,1已用',
  `create_time`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_phone_cipher` (`phone_cipher`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='短信验证码表';
```

### 2.2 服务器旧表迁移（一次性执行）`src/main/resources/db/migration/migration_v1.sql`

> MySQL 不支持 `ADD COLUMN IF NOT EXISTS`，该脚本**一次性执行**，不参与自动初始化。
> 执行前建议先查 `information_schema.COLUMNS` 确认目标列不存在。

```sql
ALTER TABLE `users`
  MODIFY COLUMN `name`  VARCHAR(64)  NULL COMMENT '姓名/昵称(兼容旧字段)',
  MODIFY COLUMN `email` VARCHAR(128) NULL COMMENT '邮箱(兼容旧字段,允许为空)',
  ADD COLUMN `nickname`      VARCHAR(64)  NULL COMMENT '昵称' AFTER `email`,
  ADD COLUMN `avatar`        VARCHAR(512) NULL COMMENT '头像URL' AFTER `nickname`,
  ADD COLUMN `phone_cipher`  VARCHAR(255) NULL COMMENT '手机号密文' AFTER `avatar`,
  ADD COLUMN `wechat_openid` VARCHAR(64)  NULL COMMENT '微信openid' AFTER `phone_cipher`,
  ADD COLUMN `apple_sub`     VARCHAR(64)  NULL COMMENT '苹果sub' AFTER `wechat_openid`,
  ADD COLUMN `is_deleted`    TINYINT      NOT NULL DEFAULT 0 COMMENT '是否注销' AFTER `apple_sub`,
  ADD COLUMN `create_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间' AFTER `is_deleted`,
  ADD COLUMN `update_time`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间' AFTER `create_time`,
  ADD UNIQUE KEY `uk_phone_cipher` (`phone_cipher`),
  ADD UNIQUE KEY `uk_wechat_openid` (`wechat_openid`),
  ADD UNIQUE KEY `uk_apple_sub` (`apple_sub`);
```

### 2.3 字段说明

| 表 | 字段 | 说明 |
| --- | --- | --- |
| users | `phone_cipher` | 手机号密文，确定性 AES，唯一索引，登录查询依据 |
| users | `wechat_openid` / `apple_sub` | 第三方登录唯一标识，唯一索引，首次登录自动注册 |
| users | `is_deleted` | 注销标记，0 正常 / 1 已注销；注销用户禁止再登录 |
| user_sms_code | `phone_cipher` | 与 users 同规则密文 |
| user_sms_code | `code` / `expire_time` / `used` | 验证码、过期时间、是否已使用（校验通过即置 1） |

## 3. 接口设计

统一响应体 `Result<T>{code, msg, data}`，`code=0` 表示成功；受保护接口通过请求头 `Authorization: Bearer <jwt>` 传递 token。

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/auth/sms/send` | 发送短信验证码 | 否 |
| POST | `/auth/login/phone` | 手机号 + 验证码登录 | 否 |
| POST | `/auth/login/wechat` | 微信登录（code 换 openid） | 否 |
| POST | `/auth/login/apple` | 苹果登录（凭证校验） | 否 |
| POST | `/auth/logout` | 登出（客户端丢弃 token） | 是 |
| GET | `/users/me` | 获取当前用户信息（手机号脱敏） | 是 |
| DELETE | `/users/me` | 注销当前用户（`is_deleted=1`） | 是 |
| GET/POST/PUT/DELETE | `/users`、`/users/{id}` | 保留原有 CRUD，返回结构不变 | 否 |

### 3.1 请求示例

```jsonc
// POST /auth/sms/send
{ "phone": "13800138000" }

// POST /auth/login/phone
{ "phone": "13800138000", "code": "123456" }

// POST /auth/login/wechat
{ "code": "wx_js_code" }

// POST /auth/login/apple
{ "identityToken": "apple_identity_token" }
```

### 3.2 响应示例

```jsonc
// 登录成功
{ "code": 0, "msg": "success", "data": { "token": "eyJ...", "userId": 1, "phone": "138****8000" } }

// 业务失败
{ "code": 1002, "msg": "验证码错误或已过期", "data": null }
```

## 5. 关键设计说明

### 5.1 确定性 AES 单列加密

- 算法：`AES/CBC/PKCS5Padding`，固定 `Key` + 固定 `IV`，加密前拼固定 `pepper` 前缀
- 特性：同一手机号 → 同一密文，因此 `phone_cipher` 可直接 `=` 查询并建唯一索引
- 使用边界：仅在 Service 层写入/回显处调用；出参默认脱敏（`138****8000`）
- 安全性说明：确定性加密理论上可被彩虹表比对（手机号空间小），通过 pepper 前缀缓解；密钥/pepper 全部走配置，禁止硬编码入仓库

### 5.2 纯 JWT 无状态鉴权

- 登录签发 JWT（payload 含 `userId`），`AuthInterceptor` 校验并解析后写入 `ThreadLocal`（`UserContext`），`afterCompletion` 清理，避免线程复用污染
- 拦截：`/users/me`、`/auth/logout`；放行：`/users`（原 CRUD）、`/auth/login/*`、`/auth/sms/send`、接口文档资源
- 登出：服务端不持久化 token，客户端丢弃即可

### 5.3 Mock 降级

| 组件 | 真实实现条件 | Mock 行为 |
| --- | --- | --- |
| `SmsSender` | 配置了短信服务商 AK/SK | 固定验证码 `123456`，仅打印日志 |
| `WechatClient` | 配置了 appid/secret | 由 code 派生模拟 openid |
| `AppleClient` | 配置了 apple 相关参数 | 由 identityToken 派生模拟 sub |

### 5.4 验证码规则

- 有效期 5 分钟；校验通过后置 `used=1` 即时失效
- 同手机号发送频率限制（默认 60 秒一次）

### 5.5 登录与注册

- 分别以 `phone_cipher` / `wechat_openid` / `apple_sub` 查询用户
- 未命中则自动注册（`is_deleted=0`）
- 命中但 `is_deleted=1` 时直接拒绝登录

## 6. 配置项（`application.properties` 新增）

```properties
# 数据源（沿用）
spring.sql.init.mode=always
spring.sql.init.schema-locations=classpath:db/schema.sql

# JWT
app.jwt.secret=please-change-me-32bytes-secret-key
app.jwt.expire-seconds=604800

# 手机号确定性 AES
app.crypto.aes-key=0123456789abcdef
app.crypto.aes-iv=abcdef0123456789
app.crypto.pepper=niujl

# 短信（留空走 Mock）
app.sms.provider=mock
app.sms.access-key-id=
app.sms.access-key-secret=

# 微信（留空走 Mock）
app.wechat.appid=
app.wechat.secret=

# 苹果（留空走 Mock）
app.apple.client-id=
app.apple.team-id=
app.apple.key-id=
```

> 生产环境务必通过环境变量覆盖 `app.jwt.secret`、`app.crypto.aes-key`、`app.crypto.aes-iv`、`app.crypto.pepper`。

## 7. 交付流程与验证

1. 在 `feature/user-center` 分支开发并提交
2. 推送分支 → 向 `main` 发起 PR → 触发 CI「Build & Test」（**不部署**），确认构建与测试通过
3. 合并到 `main` → 触发「Deploy to server」自动部署
4. **部署前**需在服务器 MySQL（库 `apiprovide`）执行一次 `migration_v1.sql`
5. 线上验证：
   - `http://niuan.top:8080/users` 可直连访问
   - `POST /auth/sms/send` → `POST /auth/login/phone` → 带 token 访问 `GET /users/me`
   - `POST /auth/logout`、`DELETE /users/me` 行为符合预期
